# MERIDIAN — MUN crisis newsroom

A fictional multi-source news aggregator built as a prop for a Model United Nations
crisis committee. All outlets, articles, people, companies and events are invented.

**Everything on this site is fiction and is labelled as fiction on every page.** Keep it
that way. Do not rename an outlet to a real one.

---

## One-time setup (10 minutes)

### 1. Make the repo

On GitHub, create a new **public** repository. Name it something obviously fake, like
`mun-crisis-newsroom`. Do not name it after a real newspaper.

### 2. Push this folder

From this folder, in Terminal:

```bash
git init
git add .
git commit -m "crisis newsroom"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/mun-crisis-newsroom.git
git push -u origin main
```

### 3. Turn on GitHub Pages

Repo → **Settings** → **Pages** → Source: **Deploy from a branch** → Branch: `main`, folder `/ (root)` → Save.

Your site appears in about a minute at:

```
https://YOUR-USERNAME.github.io/mun-crisis-newsroom/
```

That is the link you give delegates.

## During committee: run this once, then forget it

```bash
./autopush.sh
```

Leave the window open. It watches `content/articles.json`, and every time the
articles change it rebuilds and pushes automatically. **You do not touch anything
during committee.** Claude writes the article into the folder, the watcher ships it.

Your GitHub credentials stay on this machine. They are never shared with Claude,
never pasted into a chat, never stored anywhere but your own keychain.

It refuses to start if the repo, the remote, or your GitHub auth is broken — so you
find out the night before instead of mid-crisis. Ctrl-C to stop.

## The manual update loop (if you'd rather not run the watcher)

1. You message me the beat: *"reveal that the unidentified vessel was chartered through a shell company"*.
2. I append articles to `content/articles.json`.
3. You run two commands:

```bash
python3 publish.py
git add . && git commit -m "update" && git push
```

4. Delegates' open tabs pick it up on their own within 20 seconds. They do not need to
   refresh and you do not need to announce it.

### How fast is it, really

GitHub Pages is **not** instant. Realistic timings:

| Step | Time |
|---|---|
| `git push` | 1–3s |
| GitHub Pages rebuild | 20–60s, occasionally 2–3 min if GitHub is busy |
| Delegate's tab auto-polls and updates | within 20s of the rebuild |
| **Total, push to visible** | **usually 40–90s** |

So: push your beat about a minute before you want the room to react to it. If you need
something to land instantly, read it aloud and let the site catch up.

The page polls `data/articles.json` every 20 seconds with a cache-busting query string.
New filings slide in with a red edge marker and a "new filings" button appears at the
bottom of the screen. The delegate's source filter and scroll position are preserved.

Make it one command by saving this as `push.sh` (`chmod +x push.sh`, then `./push.sh`):

```bash
#!/bin/bash
python3 publish.py && git add . && git commit -m "wire update $(date +%H:%M)" && git push
```

## Files

| Path | What it is |
|---|---|
| `content/articles.json` | **Master file.** Articles + your private chair notes. Gitignored, never published. |
| `data/articles.json` | Generated by `publish.py`. Chair notes stripped. This is what delegates see. |
| `data/outlets.json` | The outlets and their dossiers. Edit to add a source. |
| `data/ticker.json` | Standing lines in the scrolling belt. Edit for live status, no article needed. |
| `publish.py` | Strips chair notes, validates, sorts by time, writes `CHAIR_NOTES.md`. |
| `CHAIR_NOTES.md` | Your crib sheet. Gitignored. |
| `index.html` | The wire feed. |
| `article.html` | Single-article reader. `article.html?id=tws-0218` |
| `sources.html` | Source Register — ownership, funding, corrections record. |

**Always run `publish.py` before pushing.** If you edit `data/articles.json` directly,
your change gets overwritten next build.

## The outlets

| Outlet | What it is | How it fails |
|---|---|---|
| **Trident Wire Service** | Cooperative wire agency | Cautious to the point of being slow. Corrects openly. |
| **The Pacific Herald** | Paper of record, investigative desk | Analysis sometimes outruns evidence. |
| **Continental Broadcasting Network** | State-funded broadcaster | Rarely false. Systematically incomplete. |
| **The Signal Post** | Ad-funded aggregator | Fast, sensational, unnamed sources, never corrects. |
| **@straitwatch** | Independent OSINT account | Often first and right. Also the source of the worst rumours. |
| **WHITE LOTUS** | Not an outlet. Transmissions. | Never wrong. Never complete. Never explains. |

No credibility score is displayed anywhere. Delegates have to work it out from
ownership, funding, sourcing and corrections. That is the exercise.

### White Lotus rules (keep these consistent)

- Always factually accurate, always incomplete.
- Never explains how it knows, never names itself, never responds to delegates.
- Appears with no submission record. The aggregator cannot explain how.
- **One transmission per 45–60 minutes of committee time.** Overuse kills it and does
  the delegates' thinking for them.

## Adding an outlet

Add a key to `data/outlets.json`:

```json
"newid": {
  "name": "Full Name", "short": "TAG", "kind": "What it is",
  "founded": "1990", "owner": "...", "funding": "...",
  "corrections": "...", "policy": "...", "tell": "How it fails",
  "color": "#333333", "accent": "#666666"
}
```

Then use `"outlet": "newid"` on articles. Filter chips build themselves.

## Article schema

```json
{
  "id": "tws-1400",
  "outlet": "tws",
  "headline": "...",
  "standfirst": "...",
  "byline": "Trident Wire Service",
  "dateline": "TAIPEI",
  "published": "2026-08-05T14:00:00Z",
  "tags": ["breaking"],
  "body": [
    "A paragraph.",
    { "type": "quote", "text": "A pull quote.", "cite": "Who said it" }
  ],
  "chairNote": "Private. Stripped before publishing."
}
```

Tags with styling: `breaking`, `correction`, `unverified`, `investigation`, `osint`, `transmission`.

## Local preview

```bash
python3 -m http.server 8000
```
